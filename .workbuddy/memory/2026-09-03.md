# 2026-09-03

## Grand Piano 三角钢琴模型系统化重写（src/scene/PianoModel.js）

完成 81 键三角钢琴的程序化建模大改：补充几何细节、修正与真琴不符之处，
全部自检通过（约 41k 三角面，152 mesh，对比原版 26k/130）。

### 修改部位
1. **琴身轮廓**（buildBodyShape）：从 Bezier/quadratic 改为 C¹ 闭合 CatmRom
   曲线（11 控制点），消除原版 bezier→quadratic 衔接处切线不连续；
   尾端 d 乘数从 1.47 修正到 1.0（关键 bug，见下）。
2. **多边形偏移**（offsetPolygon）：用"两条偏移边求交 + 斜接限幅 + 平行边
   退化为均值法"重写，解决原版"取相邻外法线均值再归一化"在近 180° 顶点
   分母趋零导致尖刺的问题（铸铁框整板因此异常外扩 0.15m）。
3. **琴键**（81 键）：从"整体垂直下压"改为"绕 balance rail 转动"（pivot
   统一在 (centerX, 0.198, 0.049)），maxAngle = asin(10mm / 前杠杆长)；
   白键圆角 0.0025m；黑键改为含 2mm 顶面倒角的 ExtrudeGeometry。
4. **击弦机**（5 节）：槌头+槌柄合并为单刚体 InstancedMesh，按 press 绕
   hammer rail 旋转（rest→hit 约 0.12 rad）；制音头+制音杆（绕后枢转动）。
5. **琴弦**（4 节）：低音段（midi<52）改用 over-stringing 交叉排布
   （前端往高音侧偏移，尾端落在低音侧 hitch 板），加 200+ 调律钉/挂弦钉。
6. **踏板琴架**（10 节）：双立柱 + 横梁从键托底面（y=0.178）直连踏板箱，
   消除原版 22cm 悬空；三块踏板绕后枢转动（前端下踩）；加三根黄铜连杆
   从踏板顶端向上连接击弦机。
7. **顶盖 + 铰链**（9 节）：加长铰链筒（沿 z 轴贯通）+ 4 颗铰链螺丝；
   LID_MAX 从 1.35rad(77°) 改 0.69rad(≈40°)，使顶端不突破 1.8m 高度约束。
8. **外壳分缝**（addShellSeams）：内框周圈暗色细缝，6 段三角形薄带读出
   "铸铁框/音板/外壳"接缝。铸铁框加 10 颗板面固定螺栓；颊木各 2 颗螺丝。
9. **弦桥**：在音板 z=−0.30 与 z=−0.62 处加两条木桥（box 几何）。
10. **铸造/反射细节**：谱架加中央支撑立柱；键前红呢条 + 后档呢。
11. **headless 保护**：woodGrainTexture / nameBoardTexture 在
    `typeof document === 'undefined'` 时返回 null（map: null 退化为纯色），
    让 tools/selfcheck.mjs 可在 Node 下离线构建。

### 修正的"与实际钢琴不符"的错误
- 琴身宽度 1.443m → 1.345m（外鼓 0.070→0.060，纳入 1.1~1.35 区间）。
- 琴身纵深 1.825m → 1.694m（DEPTH 1.60→1.48；尾端 d 乘数 1.47→1.02，
  根除 CatmRom 推尾到 2.18m 的 bug）。
- 整体高度 2.205m → 1.779m（顶盖 77°→40°，更接近真琴"长支棍"演奏位）。
- 琴键运动：垂直下压 → 绕平衡销旋转（前端 10mm，后端微抬被 fallboard 遮）。
- 踏板架与键托：22cm 悬空 → 直连。
- 琴弦：低音段平行于中音 → over-stringing 交叉。
- 铸铁框整板：偏移尖刺导致多边形异常外扩 0.15m → 求交算法稳定。

### 约束遵守
- 坐标原点 / 朝向 / keyTopY-floorY=0.72 不变。
- materials 对象键全部保留（M._seam / M._screw / M._hinge 以 _ 前缀追加）。
- group / bounds / keys Map / keyMeshes / setDamper / setPedal / updateLid /
  update / lidProgress 签名不变。
- key 对象附加 pivotY / pivotZ（旧字段保留）；KeyLabels 已更新使用二者。
- 琴键 mesh 的 userData.midi 仍由 raycaster 拾取。

### selfcheck 公式修正
原版键前端下沉测试用 sin(rotation.x) * key.length（隐含后端铰链假设），
与新平衡销枢轴矛盾。改为 sin(rotation.x) * (frontZ - pivotZ)，即真实
杠杆长，断言 7~13mm（10mm 物理下沉）。

### 面数
152 mesh / 41k 三角面（vs 原版 130 / 26k，+58%），仍在合理范围。

### 是否需要同步调整
- 贴图：无需新增贴图文件（木纹/铭牌仍为程序化 canvas）。
- 动画绑定：未触动；槌头随 press 抬起是**新增**的纯视觉行为，未改任何
  对外接口；如不需要可移除 refreshHammers 调用。
- 工具：新增 `npm run check` 通过的 headless 构建能力（之前因 document
  不可用而 crash）。

## 第二轮：修复"看不见内构 + 有突出"（用户看截图反馈）

### 根因（用射线/包围盒诊断脚本定位，非猜测）
1. **offsetPolygon 尖刺**：`Shape.getPoints(72)` 在闭合接缝处返回**重复相邻点**，
   产生零长边；其边法线退化成 (0,0)，"两偏移边求交"公式算出飞出的点。
   后果：铸铁板外扩到 x=−0.202 / z=−1.640 / z=+0.154（前端凸出 15cm），
   innerRim、soundboard 同样外扩；外壳被推到 z=−1.622（超出 DEPTH 14cm），
   自交多边形三角化后糊住整个内腔 → **内构完全看不见**。
2. **铸铁板是实心整板**：金板盖死音板/肋木/弦桥/琴弦，内腔是黑箱。
3. **铰链筒外露**：`hingeLen = DEPTH + 0.04` 且 z 定位偏移，前端凸出 4cm。
4. **音板过低 / 弦桥过矮**：SB_Y=0.10，弦桥仅 1.6cm，琴弦悬在音板上方 28cm。

### 修复（均在 src/scene/PianoModel.js）
- `offsetPolygon`：先剔除重合相邻点（含首尾接缝回环），再对 d<0 的结果
  做**源包围盒内缩 |d|*0.98 的钳制**，彻底杜绝尖刺外溢。
- 铸铁板改为**周圈边框 + 纵横梁镂空结构**（`plateShape.holes.push`，
  内孔 = 外轮廓内缩 5.5cm）；纵梁在两条弦桥处**断开留拱门**，避免梁桥互穿。
- `SB_Y` 0.10→0.26、`PLATE_Y` 0.375→0.361（板底落在内框顶面 0.35，不悬空）。
- 弦桥改为 `taperedBoxGeometry` 高桥，从音板 (SB_Y+0.008) 直达弦面
  (STRING_Y−0.005)，高约 12cm。
- 铰链筒 `DEPTH+0.04`→`DEPTH−0.04`，z 重定位，不再凸出前沿。

### 量化效果（射线采样 8×8 网格打音板，统计首命中）
| 视角 | 改前内构可见 | 改后 |
|---|---|---|
| hero（默认） | **0/64 (0%)** | **37/64 (58%)** |
| full | 4/64 (6%) | 37/64 (58%) |

改后遮挡物全部为物理合理项：开盖的顶盖 17%、外壳自身的框沿 12.5%、
谱架 12.5%。俯视/侧视/演奏视角仍为 0%，符合真琴（顶盖/谱架本就挡住）。

关键部件包围盒（改前 → 改后）：
- 铸铁板 x −0.202..1.179 → 0.063..1.113（干净内收）
- 外壳 z −1.622..0.001 → −1.521..0.000（余 4cm 为样条自然外鼓，非尖刺）
- bounds.depth 1.6018 → 1.4800

### 校验
- `node tools/selfcheck.mjs` 30 项全通过；147 mesh / 43k 三角面。
- 约束未破：原点/朝向/尺寸/命名/层级/材质绑定/对外接口均不变。
- 诊断脚本（_diag/_shape/_offset/_sight/_bbox/_domstub）已全部删除。

### 经验（可复用）
- 程序化建模里 `Shape.getPoints()` 的闭合接缝重复点是隐形杀手，凡是要对
  采样点再做几何运算（偏移、求交、放样）前必须去重。
- Node 下加载依赖 canvas 的模型文件，可先 import 一个 `document.createElement`
  桩模块（ESM 按 import 顺序求值，桩模块放在最前即可）。

## 第三轮：修复"点击按键会抬起"（用户实测反馈）

### 现象
点击琴键时键应该下压，实际却上抬。

### 根因
`src/scene/PianoModel.js` 的 `update()` 里：
`k.pivot.rotation.x = -k.press * k.maxAngle;`
pivot 局部 +z 指向演奏者（前缘 z=+0.099>0），绕 X 轴
y' = y·cosθ − z·sinθ，前缘 z>0 要使前缘下沉必须 θ>0。负号导致 θ<0 → 前缘上抬。
**selfcheck 旧断言用了 `Math.abs(...)`，只量幅度不验方向，所以这个符号错误一直没被抓到。**

### 修复
1. 改一行：`rotation.x = k.press * k.maxAngle;`（去掉负号）。
2. selfcheck 改为实测前/后缘顶面角点的**带符号**世界位移：
   前缘应 −10±1mm、后缘应 +5±1mm（绕平衡销转动，前沉后抬）。
3. 顺带实测发现**击弦机也写残了**（同一轮我新增的）：
   `SHANK_LEN=0.080` 太短、rail 太低（0.272/-0.058），槌头顶到
   y=0.351 就停，**离弦 44mm**，且击弦点落在 agraffe 之前。
   修法：rail 抬到 (0.290, -0.085)、SHANK_LEN=0.105、静止槌头
   (0.342, -0.174)（弦面下 5cm、agraffe 之后）、击弦 (0.391, -0.085)
   使毡头顶入弦面约 3.5mm；并在铸铁板前框加一道"锤线"通缝
   （plateShape.holes 加矩形 hole，z −0.160..−0.110 满宽），让槌头
   全行程穿过前框不穿插。
4. selfcheck 加"按键时槌头触弦"断言（实测 0.398，入弦面）。

### 校验
- 改后实测：前缘 −10.1mm / 后缘 +4.8mm；槌头行程 53.8mm、击弦位 0.398。
- selfcheck 30 项全通过；147 mesh / 43k 三角面。约束未破。

### 经验（可复用）
- **凡有"方向"要求的旋转/位移断言，绝不能套 Math.abs**——方向反了 abs 判不出来。
  应取明确角点做带符号的世界位移比较。
- 旋转符号靠心算易错：用脚本取"前缘/后缘某角点"的世界坐标实测位移，比推导稳。
- 击弦机/琴键这类靠旋转摆动的动作，先确认"静止点必须落在某几何边界之下
  （如槌头顶静止低于铸铁框底 0.350）"，再确认"击弦点能到达目标"，二者都要满足
  否则必然穿模——遇到穿过板件时，给板件对应位置开 hole 比挪动整条动作更稳。

## 第四轮：修复"钢琴上多了一个黄条"（用户截图反馈）

### 现象
截图显示键盘后方有一条贯穿左右、高于 fallboard 的亮黄色横条。

### 根因
通过列出所有金色/黄铜部件的世界包围盒并对比截图位置，确定该黄条是
**前弦枕（agraffe）**：一块 `BoxGeometry(KW*0.94, 0.028, 0.030)` 的金色长条，
位于 `(cx, PLATE_Y+0.014, -0.11)`，即 fallboard 顶（y≈0.34）上方约 2cm 处。
从默认相机 (1.5, 1.35, 1.9) 的俯视角度看，它正好在黑色 fallboard 上方形成
一条醒目的亮黄色水平带，被用户感知为"多出来的黄条"。

### 修复
`src/scene/PianoModel.js`：
- 将 `agraffe` mesh 注释掉（保留代码与注释说明）。琴弦仍由前后弦钉锚定，
  移除的是这个装饰性的金色横条。
- 未改动铸铁框主体、击弦机、琴键动画等，避免连锁影响。

### 校验
- `node tools/selfcheck.mjs` 30 项全通过；146 mesh / 43k 三角面。
- 约束未破：原点/朝向/尺寸/命名/层级/材质绑定/对外接口均不变。
- 诊断脚本（_yellow/_bbox/_yellowmap/_plateverts* 等）已全部删除。

### 经验（可复用）
- 用户说"多了一个 X 条"时，先用包围盒/材质过滤列出所有候选几何体，
  再对照相机视角判断最可能是哪一块；不要直接猜测材质或整体改色。
- 装饰性零件（铭牌、agraffe、压弦条等）虽然符合真琴结构，但在低多边形
  风格或特定相机角度下容易退化成"突兀的色块"，必要时可直接移除或替换
  为更不抢眼的表示。

## 第五轮：黄条仍未消失——继续遮铸铁框顶面

### 现象
移除 agraffe 后用户反馈黄条仍在。新截图显示金条位置略高于 fallboard 顶，
贯穿键盘后方。

### 根因
黄条实际由两部分叠加：
1. agraffe（已移除）；
2. **铸铁框（platePanel）顶面**：`PLATE_Y=0.361`、厚度 0.022，顶面在
   `y≈0.372`，比 fallboard 顶（`y≈0.34`）高出约 3cm。从俯视角度看，
   fallboard 黑面顶部的这 3cm 金边形成连续亮带。

### 修复
`src/scene/PianoModel.js`：
- **fallboard 加高**：高度 `0.16→0.19`，中心 y `0.260→0.275`，顶面到
  `0.370`，正好遮住铸铁框顶（0.372）。
- **铭牌同步上移**：y `0.262→0.277`，保持在 fallboard 前表面中央。
- **谱架整体抬高**：group y `0.37→0.40`，避免与加高的 fallboard 穿插。
- **谱架中央支撑柱改短上移**：圆柱高度 `0.075→0.050`，局部 y
  `-0.038→+0.015`，使其从 fallboard 顶连到谱架面板底，不再穿过 fallboard。

### 校验
- `node tools/selfcheck.mjs` 30 项全通过；146 mesh / 43k 三角面。
- 约束未破：原点/朝向/尺寸/命名/层级/材质绑定/对外接口均不变。

### 经验（可复用）
- 当"移除装饰件"不能解决问题时，要回到相机视角做高度/深度分析：
  亮条常常是某金属面在遮挡物顶面之上露出的"顶边"，此时加高遮挡物
  比改材质或删零件更稳。
- 调整一个垂直面板时，要同步检查同区域的相邻部件（铭牌、谱架、支撑柱），
  否则易产生新的穿插。

### 修正：符号键 `]` 落在黑键（用户反馈"【】应该都是白键"）
初版把 `[ ] \` 接成连续半音 offset 29/30/31 → F5 / **F#5** / G5，
其中 `]`=F#5 是黑键，瀑布卡片显示深色、且 3D 琴键压下的是黑键。
用户期望符号键都是白键。

修正：符号键落在**白键序列**（P=E5 之后的白键为 F5 G5 A5），
即 `BracketLeft:29, BracketRight:31, Backslash:33`（跳过黑键 F#5/G#5）。
- `OFFSET_LABELS` 末尾补为 `['[', '', ']', '', '\\']`（索引 29/31/33 有键，
  30/32 为空字符串 = 无对应物理键）。
- `labelForOffset` 改为 `(l && l.length) ? l : null`，空串按"无键"处理，
  避免黑键 F#5/G#5 在键面模式显示幽灵空标签（KeyLabels 遇 null 会 skip）。
- 联动：`selfcheck` 断言 `0~33` / `长度=34`；`ControlPanel` 八度范围显示
  `baseMidi+33`（面板默认 "C3 ~ A5"）；`InputManager._shiftOctave` 守卫
  `next + 28 > endMidi` → `next + 33`，避免平移后 A5 越界。
- 经验：**扩展"接在末尾"的物理键时，要按真实白/黑键序列跳半音，
  而不是简单连续 +1**，否则会错落在黑键上。

## 录制 + 循环回放功能（src/app/Recorder.js + PianoApp/ControlPanel/index.html）

用户需求：新增录制功能，记录弹过的音符并可循环重复播放。

### 实现
- 新增 `src/app/Recorder.js`：`captureOn/captureOff` 由 `PianoApp.pressNote/
  releaseNote` 钩子调用，采集 `{ t(秒), midi, v, type:'on'|'off' }`。
  自身回放 source='rec' 不二次录制（防反馈）。`start/stopRecord/clear`，
  `play(loop)` 把 on/off 配成 `{t,d,m,v}`（与示范曲同格式）用 setTimeout
  对齐视觉、AudioContext 时钟对齐发声，循环尾隙 0.6s；用 `_token` 让
  stop 后待执行回调作废，`_recHeld` 在循环边界释放残留音。
- `PianoApp`：构造里 `new Recorder(this)`；`pressNote` 末尾 `captureOn`、
  `releaseNote` 在 held 清空后 `captureOff`（均用 `?.` 防空）。
- `ControlPanel`：绑定 `btn-rec`(toggleRecord) / `btn-rec-play`(先 ensureAudio
  再 play(true)) / `btn-rec-stop`(stopPlay) / `btn-rec-clear`(clear)；
  新增 `setRecorderState` 联动按钮态与 `#rec-status`（已录音符数）。
- `index.html`：面板新增"录制"区块（●录制 / 循环播放 / 停止 / 清空 + 状态行）。
- 录制期间弹示范曲('demo' 源)也会被录进去，可借此把示范曲变循环。

### 校验
- 三个模块 `node --check` 语法 OK；`selfcheck.mjs` 全通过。
- 回放在浏览器内手动验证（本地服务 127.0.0.1:8123）。

### 注意
- `_compile` 按 midi 配对 on/off，多来源重叠(如循环+手动同音)边缘情况可能
  轻微错位，单来源演奏完全正确。
- 录制用 performance.now()、回放用 setTimeout/AudioContext，仅浏览器环境，
  未被 selfcheck 覆盖（selfcheck 不实例化 PianoApp）。

### 修复：循环回放结尾空档过长、听感不连贯（src/app/Recorder.js）
现象：录完后最后演奏的音符之后还会空很久，循环听起来像卡住再重来。
根因有两点叠加：
1. `_compile` 里未闭合音符（一直按到停止录音仍没松）的时长 = `end − 按下时刻`，
   而 `end` 是**录音停止的时间戳**，把"停录前那段发呆静音"也算了进去 → 尾音被拉长。
2. `play` 里循环周期固定 `最后音符 end + 0.6s`，在此之上再加尾隙 → 更空。

修复：
- `_compile` 重构：音频时间轴只算到"最后一个有 off 的音符"的真实结尾
  （lastClose），**不再含停止时刻的静音**；仍按着没松的音用一个自然收尾
  上限 `onEnd = max(lastOnT, lastClose) + TAIL`，保证该音与前面连续且不会无限长。
- 新增模块常量 `const TAIL = 0.28`（回放末尾收尾静音）。
- 新增 getter `duration` = 最后音符自然结尾 + TAIL。
- `play` 循环周期改用 `Math.max(this.duration, 0.01)`，替换原 `end+0.6`。
- Node 单元验证：事件末尾静音到 3.0s 时，编译后 lastEnd≈0.90（非 3.0）PASS；
  最后音按住不松时 lastEnd≈0.78（自然收尾）PASS。
- 经验：录制"总长"应取**音频内容**（最后闭合音符 + 短尾），而非"按下停止的
  墙钟时刻"，否则停录前的停顿静音会被固化进循环周期。

### 修复：录音起点应锚定"第一个音响起"而非"点录制按钮"（src/app/Recorder.js）
现象：点"录制"后如果先停顿几秒再开始弹，录音开头会带着这段等待的空白，
循环时开头有一截空档。用户要求"录制开始时按第一个音开始算"。
修复：事件时间轴不再以 startRecord 的墙钟为 0，而是**惰性锚定到首个音符**：
- 构造 `_t0 = null`（null = 尚未弹第一个音）。
- `captureOn` 首个音时 `_onFirstNote()` 把此刻定为 `_t0`（=0），
  之后 `_eventT()` 一律 `(performance.now() - _t0)/1000`，故录音从第一个键响起算。
- `captureOff` 在 `_t0===null`（还没弹任何音）时直接忽略。
- `stopRecord`：若 `_t0===null`（一个音都没弹）→ 不产出录音（count 0）；
  否则仍按住的首音用 `(performance.now()-_t0)` 补 off，`_compile` 再修剪。
- `clear` 也重置 `_t0=null`。
- Node 仿真：点录制→干等2s→弹C3(0.4s)→空1s→弹E4→0.5s后停止；
  事件 [on C3 t=0, off 0.4, on E4 1.4, off 1.9]，首个音 t=0、无开头空白 PASS。
- 经验：录音计时器要么在"真正发声"时才归零，要么存绝对墙钟并在首个事件处
  定零点；不要以"按下开始按钮"的时刻当录音起点。

### 自动结束录制：最后一个音松开即停（src/app/Recorder.js）
现象：用户希望"尾节点松开后立即结束录制"，不用再去点停止按钮。
修复：
- 新增构造字段 `this.autoStop = true`。
- `captureOff` 在删除该音的 held 记录后判断：`if (this.autoStop && this._held.size === 0) this.stopRecord();`
  —— 只有**所有按住的音都松开**（真正的最后一个音 release）才触发自动停止；
  和弦里松开某一个音但还有其他音按着时不会误停。
- 自动停止走既有 `stopRecord`：此路径下 `_held` 已空，不会补多余的 off，
  录音结束时刻 = 最后一个音的 release，无尾部静音；UI 经 `setRecorderState`
  收到 {recording:false, count:N}，按钮自动回到"● 录制"、计数更新。
- Node 仿真（C3按住+0.3s按下E4，先松E4再松C3）：松E4仍录制 PASS；
  松C3自动停 PASS；两音齐全；emit 序列 {rec:true}→{rec:false,count:2} PASS。
- 体验：录完后按钮自动复位，可立刻点"● 录制"录下一遍；无需手动停止。
- 经验：录制要"松最后一个音即停"，关键是判别**当前按住集合是否为空**，
  而不是"是否收到了 off"——否则和弦/多音会提前误停。

## 音符（Piano Roll）编辑器（src/editor/* + Recorder 改造）

新增一整套"Piano Roll 编辑器"，对标 FL Studio / Ableton 的 Piano Roll
交互，可对刚录制的音符做精细修改：选择（单/多）、拖动平移（音高+时间，整半音吸
附、50ms 时间吸附）、拖两端改时长、删除、复制粘贴、撤销/重做、试听、应用；
界面完整：Canvas 2D 渲染 + 工具栏 + 覆盖层。

### 文件
- `src/editor/NoteTimeline.js` — 可编辑文档模型（基于快照的撤销/重做栈）。
  每音带内部 `id`，对外仍输出 `{t,d,m,v}`；原语：`apply/commitHistory/insert/remove/translate/resize`。

  一次（一次拖拽 = 一次撤销）。
- `src/editor/NoteEditorController.js` — 接管 Recorder ↔ NoteTimeline ↔ Editor：
  进入时载入可编辑音符；工具栏"应用"剥掉 id 写回 `Recorder.setEditedNotes()`，
  "放弃"只销毁编辑器不改 Recorder。
- `index.html` — 新增 `.editor-host` 覆盖层 + `.pro` 工具栏/画布骨架；面板新增
  `音符编辑器` 入口按钮。
- `styles/main.css` — `.editor-host` 与 `.pro-toolbar/. .pro-body/. .pro-canvas`
  样式（卡片化、毛玻璃背景）。

### Recorder 改动（向后兼容）
- 新增 `editedNotes: Array<{t,d,m,v}>|null` 覆盖层、`setEditedNotes(notes)`、
  `editableNotes()`（覆盖优先）、`_sourceNotes()`、`audition(notes)`（单次试听）。
- `play()` 改走 `_sourceNotes()`，输出仍是同形 `{t,d,m,v}`；`duration`/循环计算
  同时维护于覆盖与原 events 两条路径。
- **原 `events` 永不被编辑器改动**；"放弃"只需 `setEditedNotes(null)`。

### 验证
- Node 单元测试：`NoteTimeline` translate/commitHistory/undo/redo 全 PASS；
  Recorder 录制 → 编辑删除 → setEditedNotes → editableNotes 走覆盖、输出纯
  `{t,d,m,v}` 不含 id、清空后回退原始录音 — 全 PASS。
- 浏览器 smoke test：覆盖层正常打开、画布 1198×612、绘制 3 音正确显示、无
  PAGEERROR；删除/撤销/重做/应用往返工作正常；最终源长度随编辑更新。
- `selfcheck.mjs` 仍全通过（编辑器代码不影响建模自检）。

### 经验
- 编辑器与原录制的数据兼容：关键是"对外只暴露 `{t,d,m,v}`"（不外泄内部 id）；
  Recorder 提供 `setEditedNotes` 覆盖层既保留原 events，又能无缝切换回放源。
- 拖拽的撤销粒度 = 一次拖动：拖动期间 `apply(commit:false)` + 收尾

### 修复：编辑器拖动音符音高方向反了（src/editor/PianoRollEditor.js）
现象：在 Piano Roll 里把音符往**上**拖，音高反而**降低**（方向反）。
根因：`move` 的音高位移 `dmRaw` 写成 `d.refM - this.yToMidi(p.y)`（减号方向反）。
本编辑器 y 向上增大代表音高更高（`midiToY`：midi 越大 y 越小/越靠上），
所以"向上拖"（p.y 变小）应让 `yToMidi` 增大 → 位移应为
`this.yToMidi(p.y) - d.refM`（新 - 旧）。
修复：改成 `dmRaw = this.yToMidi(p.y) - d.refM`。
数值验证：C4(m60) 上拖一行，指针处 yToMidi=61；旧式 dm=-1（方向反），
新式 dm=+1（升音高）正确。
浏览器实测：上拖2行 m48→m50、右拖~60px t0→0.15，无 PAGEERROR。
- 经验：凡"屏幕坐标 → 音乐量"的反向轴（屏幕 y 上大音高高，即 midi 大=靠上），
  位移一律用 **（新指针值 - 旧指针值）**，不要凭直觉写成反之；可先数值推演。
- 注意 resize-start / 双击新建 / 框选 用的是 yToMidi 直接映射或仅时间轴 x，
  不涉及反向 delta，未受影响；唯独 move 那一个减法需要反转。

### 修复：编辑器关闭后再打开打不开（PianoRollEditor.destroy 误清宿主骨架）
现象：第一次能打开，关闭(应用/放弃)后再次点"音符编辑器"毫无反应。
根因：`PianoRollEditor.destroy()` 写了 `this.root.innerHTML = ''`，而 root 是
**整个 host(#note-editor)** —— 它把静态的 `.pro-toolbar`(按钮) 和 `.pro-body`
全清了。第二次 open() 时 `querySelector('.pro-canvas')` 为 null →
`new PianoRollEditor` 里 `this._canvas.getContext` 抛错 → 打不开。
另外每次 open 都对静态按钮 `addEventListener('click',...)` 会重复累积监听。
修复：
1. `PianoRollEditor.destroy()` 改为只 `removeEventListener` 并移除它持有的那个
   canvas 节点（`parentNode.removeChild(canvas)`），绝不 innerHTML='' 清骨架。
2. `PianoRollEditor._bind()` 不再绑定静态工具栏 `[data-act]`；工具栏动作统一由
   `NoteEditorController._bindToolbar()` **在构造时绑定一次**，经 `_toolbar(act)`
   转发给当前 `this.editor`（不存在则忽略），避免重复累积。
3. `NoteEditorController.open()` 在实例化前先确保 `.pro-body` 内有一张全新
   `.pro-canvas`（上次 destroy 已移除旧画布），再 `new PianoRollEditor`。
浏览器实测：apply/reset/apply 三次 打开→关闭→再打开 均成功、画布重建、无
PAGEERROR。
- 经验：不要把"整个宿主的静态骨架"和"运行时动态画布"混在同一个容器的
  innerHTML 里销毁；骨架应常驻，销毁只应移除动态子节点；静态按钮的监听要
  "绑定一次 + 转发到当前实例"，否则开关多次会叠监听。
